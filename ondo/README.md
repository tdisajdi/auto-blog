# ondo 코드 안내 - 신문사 부서 구조

| 부서 | 폴더 | 하는 일 |
|---|---|---|
| 설정 | `config.py` | 사이트 이름·색, 분야 목록, 한국 시간 - 여러 부서가 같이 쓰는 값 |
| 키 이름표 | `keys.py` | Gemini 키 "이름표:키" 읽기, 거부된 키를 이름표로 텔레그램 알림 |
| 취재부 | `sources/` | 자료 모으기 (트렌드, KOSIS, EIA, 뉴스, 가격) |
| 기획부 | `desk/` | 주제 고르기·추천 |
| 편집국 | `writing/` (+ `prompts/` 지침서) | 기획 회의 → 한 번에 쓰기 → 고쳐쓰기 |
| 교열부 | `checks/` | 자동 점검, 편집장 검토, 중복 검사, 편집 기록부 |
| 디자인부 | `media/` | 썸네일, 차트, 사진, ComfyUI 그림 |
| 발행부 | `publish/` | 워드프레스, 검색엔진 알림 |
| 고객창구 | `telegram/` | 추천·승인·메모·그림 받기·알림 |
| 시험실 | `../tests/` | 자동 시험 (깃허브가 코드 바뀔 때마다 실행) |

## 옮기는 순서 (2026-10-31 결정)
1. 뼈대 + 설정 + 시험실 + 실패 알림 (완료)
2. 새 편집국 (두 번째 글·ETF 가이드부터) (완료 2026-10-31) ← 실제 글로 확인 중
3. 나머지 부서를 하나씩 옮기기 (옮길 때마다 시험 통과 확인)
4. ETF 종목 분석 글도 새 편집국으로

각 부서 폴더의 `__init__.py` 맨 위에 "지금 위치"(아직 옮기기 전 코드가 있는 파일)를 적어 두었다.

## 편집국 흐름 (writing/desk.py)
1. 기획 회의: 섹션 3~4개 + FAQ, 섹션마다 쓸 사실을 나눠 배정(중복 방지), 표는 1개만
2. 한 번에 쓰기: 좋은 모델(WRITER_MODEL_PRIORITY) 한 번 호출로 글 전체
   - 좋은 모델이 모든 키에서 한도(429)거나 답이 잘리면 → 섹션별 나눠 쓰기(섹션마다 다른 키,
     설계도 전체 + 앞까지 쓴 글을 같이 줌) → 이음새 다듬기 1번
3. 교열(코드): Part 번호·마크다운·<img>·중복 문단은 바로 고치고, N/A·표 빈칸·흐린 출처·표 2개·
   비슷한 문장 반복·같은 숫자 4번 이상·너무 얇은 글은 지적
4. 숫자 대조(코드): 자료에 없는 숫자를 찾아 고쳐쓰기 때 전달
5. 검토 담당 3명(사실 검증 / 독자 편집 / 정책·신뢰): 문제마다 심각도와 본문 인용. 점수는 코드가 계산.
   통과 = 0.7 이상 + 치명·중요 0개 + 교열 지적 0개. 아니면 고쳐쓰기(최대 2번). 통과한 판을 우선으로 씀.
   자동 발행은 꺼져 있음(AUTO_PUBLISH=1일 때만 공개 발행) - 통과해도 임시글로 올리고 알림.
6. 전부 편집 기록부 logs/YYYY-MM/DD-종류-주제.json에 기록(모델, 키 번호, 실패 이유, 점수, 지적, 고친 것).
   주간 상태 점검 리포트에 요약이 붙는다.
