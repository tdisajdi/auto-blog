[핵심 설계 결정 — 왜 이렇게 했는지]
- ETF는 "발굴→토론(후보 비교)→기획(고정 골격)→글쓰기→검수" 구조를
  그대로 유지. ETF는 실제 데이터 기반이라 고정 골격으로 충분하다고
  판단해서 기획 부서는 안 건드림 (사용자가 명시적으로 결정한 부분).
- 뉴스(테크/바이오/특허)는 반대로 "기획 부서가 매번 다른 목차를 진짜로
  고민해서 만든다"는 컨셉으로 재설계 — 독립적으로 목차 초안 3개를
  만든 뒤 토론/판정으로 하나를 확정하는 방식 (메뉴 선택형 아님).
  이것도 사용자가 명시적으로 요구해서 바뀐 방향.
- "사후교정(targeted-fix)": 품질검사에서 걸린 부분만 그 부분만 다시
  쓰게 하는 기능. 원래 ETF 코드에 이미 있었는데 안 쓰이고 있었음 →
  뉴스 파이프라인에도 연결해서 실제로 작동하게 만듦.
- GitHub Actions 완전자동화: ETF는 텔레그램 승인 거쳐서 발행(투자
  리스크 있어서), 뉴스 3종은 승인 없이 완전자동(시의성 때문에).
- 통합키(DOTENV_CONTENTS): API 키 10개+ 를 깃허브 시크릿에 하나하나
  등록하지 않고, .env 파일 전체 내용을 시크릿 하나로 등록 →
  워크플로우가 실행될 때 그 내용을 .env로 복원해서 사용.

[작업 중 발견/수정한 실제 버그들 — 참고용]
- f-string 안에 같은 따옴표 중첩, 백슬래시 포함 — Python 3.11에서
  SyntaxError. 로컬 변수로 미리 빼서 해결.
- _load_json_file 중복 정의 — pyflakes로 발견, 조용한 쪽(로깅 없는
  버전)이 실제로 쓰이고 있었음. 하나 삭제.
- 캘린더 히트맵 함수에서 chart_js를 만들어놓고 HTML에 안 넣던 버그.
- news_engine.py에서 _clean_redundant_parenthetical, _safe_html_filter
  둘 다 (content, issues) 튜플을 반환하는데 언패킹 안 하고 그냥 변수에
  담아서 TypeError 났던 버그 2건 — 실제 모의 실행 테스트로만 발견됨
  (정적 분석/컴파일 체크로는 안 잡힘). 전체 파이프라인을 가짜 데이터로
  끝까지 돌려보는 테스트가 꼭 필요했음.
- PROMPT_LOGIC_VERSION을 blog_engine.py로 잘못 옮겼다가, 실제로는
  ETF 전용 상수라서 etf_auto.py로 다시 되돌림.
- _register_article 호출부 6곳이 리네임 전 키워드(etf_data=)를 그대로
  쓰고 있어서 고침.

3-1. 워드프레스 자동 발행 방식 — 왜 "토큰 방식"인가
=================================================================
[처음에 안내했던 쉬운 방식 — 실패해서 버림]
- "애플리케이션 비밀번호" 방식: 워드프레스 설정에서 앱 비밀번호를
  만들어 WP_USERNAME / WP_APP_PASSWORD로 넣고, 사이트 주소의
  wp-json/wp/v2/posts 로 글을 보내는 방식.
- 실패 이유: 이 방식은 직접 서버를 운영하는(자체 호스팅) 워드프레스용.
  ondo 사이트는 WordPress.com에 올라가 있는데, WordPress.com은 이
  경로를 요금제와 상관없이 막아둠. 그래서 비밀번호를 새로 만들어도
  계속 "401 rest_cannot_create" 에러가 났음.
  (요금제를 올려야 하는 문제가 아니라 방식 자체가 안 맞았던 것)

[지금 쓰는 방식 — OAuth2 토큰]
- WordPress.com이 공식으로 열어둔 별도 창구
  (public-api.wordpress.com/rest/v1.1)를 "토큰"으로 호출함.
  무료 요금제에서도 작동.
- 필요한 값: WP_OAUTH_TOKEN(토큰), WP_SITE_ID(사이트 번호).
  WP_SITE_URL은 RSS 수집과 글 주소 추정에 계속 씀.
- 덤으로 좋아진 점: 태그를 이름 그대로 보내면 워드프레스가 알아서
  만들어줌(예전 방식은 태그 번호를 일일이 찾아야 했음). 글 주소
  (슬러그)도 직접 지정 가능.

[토큰 받는 법 — 딱 한 번, 만료/취소되면 다시]
1. developer.wordpress.com/apps 접속 → "Create New Application"
   - Redirect URLs 칸에 http://localhost 입력, 나머지는 대충 채워도 됨
   - 저장하면 나오는 Client ID / Client Secret 복사
2. 내 컴퓨터에서 python get_wp_oauth_token.py 실행
   (이 스크립트는 저장소에 들어 있음)
3. Client ID / Secret 입력 → 화면에 나온 주소를 브라우저로 열고
   로그인 후 Approve
4. 브라우저가 http://localhost/?code=... 로 넘어가면서 "연결할 수 없음"
   이 떠도 정상. 주소창 전체를 복사해서 스크립트에 붙여넣기
5. 스크립트가 WP_OAUTH_TOKEN=..., WP_SITE_ID=... 두 줄을 출력함
   → .env에 넣고, DOTENV_CONTENTS 시크릿도 새 내용으로 갱신
- 401 에러가 나면 토큰이 만료/취소된 것 → 위 과정을 다시 하면 됨.
- 참고: 스크립트는 권한을 "posts"(글쓰기)만 요청함. 나중에 카드뉴스
  이미지나 IndexNow 파일 업로드(미디어 라이브러리 사용)가 실패하면,
  스크립트의 scope 값을 늘려서 토큰을 다시 받아야 할 수 있음.
  ETF 글 발행 자체에는 영향 없음.

[예비 경로 — 토큰 방식이 실패할 때]
1. Selenium(WP_EMAIL/WP_PASSWORD): 프로그램이 브라우저를 직접 열어
   로그인하고 글을 붙여넣음. 워드프레스 화면 구조가 바뀌면 깨질 수
   있어서 예비용으로만 둠. (뉴스 3종은 브라우저를 안 띄워서 이 경로 없음)
2. 반자동: 그것도 실패하면 글을 복사해두고 직접 붙여넣도록 안내.
